# Boss 技能清晰化设计与实现方案

## 目标

让每个 Boss 技能都满足以下四点：

1. 玩家能一眼看出技能作用到了哪里
2. 玩家能理解技能到底改变了哪些宝石/格子状态
3. 技能影响会持续到足以形成决策压力，而不是一闪而过
4. 技能描述、棋盘表现、实际结算三者一致

---

## 统一实现思路

### 1. 机制层

每个技能必须先落到可计算的棋盘状态上，而不是只写提示文案或播放特效。

推荐统一状态类型：

- `burning`：灼伤，首次清除只熄火，可扩散
- `frosted` / `lockedTurns`：冻结/封锁，不可交换或需额外清除
- `armored`：护甲，需要额外命中
- `poisoned`：污染，可扩散/减收益/触发二次扰动
- `overloaded`：过载，回合后扰动颜色或位置
- `illusion`：伪装，显示与实际不完全一致
- `voidmark` / `rift`：虚空裂口或终局类高压标记

### 2. 结算层

每个状态都必须明确：

- 何时施加
- 何时衰减
- 何时扩散或升级
- 遇到消除时如何处理
- 和玻璃、锁定、障碍、特殊宝石如何交互

### 3. 表现层

每个技能至少有三层反馈：

- 棋盘反馈：受影响格子有明确视觉变化
- 提示反馈：Boss 施法名 + 浮字 + 警告语
- 技能书反馈：描述直接说明效果与应对方式

### 4. 文案层

技能文案不能只写气氛词，必须写后果。

例如：

- 不推荐：狐火包围关键格子
- 推荐：点燃 6 枚宝石并短暂锁定 2 枚；未处理的火焰会在下回合扩散

### 5. 验证层

每个技能都必须通过以下检查：

- 不看代码，玩家能否看懂棋盘状态
- 不看棋盘，只读文案，能否理解规则
- 是否存在持续压力
- 是否存在可操作应对策略

## 火系 Boss 作为标杆的设计结论

### 已建立原则

- 火焰技能不只是一层轻特效，而是明确状态：`burning`
- 灼伤宝石首次清除只熄火，第二次才真正消除
- 若本回合未处理，下一回合向周围随机扩散 1~2 枚
- 视觉应克制但清晰：浅底色 + 小标签 + 轻外框

### 火系技能设计模板

- 小技能：点燃少量宝石，建立认知
- 中技能：点燃 + 行/区域限制
- 大技能：点燃 + 锁定/压力减步 + 扩散威胁
